# Implementation Plan: HAProxy SPOA Plugin Hub

**Branch**: `001-spoa-plugin-hub` | **Date**: 2026-03-30 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/001-spoa-plugin-hub/spec.md`

## Summary

Build a HAProxy SPOE agent hub in Rust that dynamically loads plugin
shared libraries at runtime, dispatches SPOE messages to configured
plugins (executing independent plugins in parallel), and returns
aggregated transaction variables to HAProxy. The hub uses `abi_stable`
for type-safe plugin loading with load-time ABI verification, and
`spop` for the SPOE wire protocol. It listens on both Unix domain
sockets and TCP, provides structured JSON logging to stderr, and
exposes Prometheus metrics via a built-in HTTP endpoint.

## Technical Context

**Language/Version**: Rust (stable, >= 1.86, edition 2024)
**Primary Dependencies**: spop 0.11, abi_stable 0.11, tokio 1, tracing 0.1, metrics 0.24
**Storage**: N/A (stateless message processing)
**Testing**: cargo test (unit), integration tests with mock SPOP client
**Target Platform**: Linux x86_64 (primary), other Unix targets secondary
**Project Type**: CLI daemon (system service)
**Performance Goals**: <100μs plugin dispatch overhead, <1ms p99 pass-through latency, 10k concurrent connections
**Constraints**: Minimize heap allocations on hot path, no lock contention during parallel plugin execution
**Scale/Scope**: 10,000 concurrent SPOE connections, unbounded plugin count (practical limit: dozens)

### Source Code (repository root)

```text
Cargo.toml                     # Workspace root
crates/
├── hub/
│   ├── Cargo.toml             # Binary: haproxy-spoa-hub
│   └── src/
│       ├── main.rs            # Entry point, CLI, signal handling
│       ├── config.rs          # TOML config parsing and validation
│       ├── listener.rs        # Unix + TCP listener setup
│       ├── connection.rs      # Per-connection SPOP handling
│       ├── dispatch.rs        # Message → plugin routing + parallel exec
│       ├── plugin_loader.rs   # abi_stable plugin loading + ABI check
│       ├── registry.rs        # Plugin registry + execution plan builder
│       └── metrics.rs         # Prometheus metrics setup + recording
└── plugin-api/
    ├── Cargo.toml             # Library: haproxy-spoa-hub-plugin-api
    └── src/
        ├── lib.rs             # Re-exports, define_plugin! macro
        ├── types.rs           # SpoeMessage, SpoeValue, ProcessingResult, etc.
        └── plugin_trait.rs    # #[sabi_trait] SpoePlugin + PluginMod

examples/
└── noop/
    ├── Cargo.toml             # cdylib: example no-op plugin
    └── src/
        └── lib.rs             # Minimal plugin implementation

tests/
├── integration/
│   ├── spop_client.rs         # Mock SPOP client for integration tests
│   ├── test_single_plugin.rs  # US1: basic dispatch
│   ├── test_parallel.rs       # US2: parallel execution
│   ├── test_transport.rs      # US3: Unix + TCP
│   └── test_plugin_errors.rs  # Edge cases: timeout, panic, ABI mismatch
└── common/
    └── mod.rs                 # Test helpers, fixture setup
```

**Structure Decision**: Cargo workspace with two crates (hub binary +
plugin-api library) plus an example plugin. The plugin-api crate is
independently publishable to crates.io. Integration tests live in a
top-level `tests/` directory to test the full binary with real plugin
`.so` files.
